# Master Leonard

A ram-skull avatar for a 480x320 USB panel (3.5" TURZX). Its eyes show what your Claude Code sessions are doing.
One exe does everything: `bin\leonard.exe`.

> **Art not included.** The ram skull this was built around is other artists' ASCII art and is not redistributable,
> so this repository contains only the code. Put your own images in `assets/source` (see its README) and
> `.\build.ps1` turns them into the sprites. Windows + a C compiler (gcc / MinGW) + Python 3 with Pillow and numpy.

| Mood | Eye | When |
|---|---|---|
| sleepy | dim amber line | no Claude session open |
| idle | amber | session open, quiet |
| thinking | cyan | a session is working |
| happy | green | a run that used tools finished (a task) |
| speaking | pale yellow flicker | a plain chat answer finished |
| alert | red, whole screen flips to a black & white negative every 0.5 s | a session needs you (permission / input) |

With several sessions, the highest in this order is shown (the table is `PRIORITY` in `src\avatar.h`):
**alert > happy > speaking > thinking > idle > sleepy**. A session needing you always wins; a finished task or
answer shows over sessions that are still working; happy / speaking last about 6 s, then that session counts as idle.
A "thinking" session that goes silent for 2 minutes (Esc, closed window, crash) settles to idle.

## Use

```powershell
.\build.ps1                 # regenerate everything + build bin\leonard.exe
.\install.ps1               # startup shortcut + Claude Code hooks (run once; -Uninstall to remove)
.\bin\leonard.exe --preview # show a 2x preview window (the normal mode has no window at all)
.\bin\leonard.exe --stop    # stop the background copy
.\tests\test.ps1 -Real      # full test (-Real = also two short headless Claude sessions)
```

`leonard.exe` modes: *(none)* background app · `--hook` the Claude Code hook (reads JSON on stdin, sends one UDP
packet, exits in ~6 ms) · `--preview` · `--stop` · `--stale N` · `--dump mood dir out.ppm [ms]`.

- `--preview` replaces a running copy, so a window always appears. The window's X only **hides** it (the app keeps
  listening); `q` / Esc in the window quit the app; to show it again run `--preview` again.
- `--hook` only acts when hook data is piped in (which is how Claude Code calls it). Typed by hand it is ignored, so
  `leonard.exe --hook --preview` simply opens the preview.

## Layout

```
bin/leonard.exe        the program (built, not committed)
src/                   leonard.c (app + hook + preview), avatar.h (moods, priority, shared)
gen/                   generated headers: panel.h (480x320 poses), sprites.h, impure.c (not committed)
assets/source/         YOUR source images go here (side-view and front-view ASCII skull) - see its README
assets/art/            the transcribed ASCII art, generated by build.ps1 (not committed)
tools/                 python generators and preview tools; paths.py knows the layout
tests/                 test.ps1 (behaviour), check_render.py (pixels)
legacy/terminal/       the terminal version of the avatar (dev tool)
build/                 scratch output - safe to delete
```

Runtime files: `%LOCALAPPDATA%\MasterLeonard\status.txt` (shown mood + each session's mood) and `events.log`
(every event received, for debugging).

## How it fits together

`Claude Code hook` -> `leonard.exe --hook` -> UDP 127.0.0.1:47474 -> `leonard.exe` (background) merges all
sessions -> picks the mood -> draws the 480x320 frame. **Sending that frame to the USB panel is not written yet**:
it goes at the marked spot in `main` (`src\leonard.c`) once the hardware is here (Turing / TURZX serial protocol).

Claude Code on this machine runs hooks through bash, so the hook path in `settings.json` uses forward slashes.
Hooks are read when a session starts.
